===============================================================================

yt-dlp 2026.07.04 from install.sh's virtualenv, reached over the network.
The window is the real IpodWindow with the real CSS, driven by putting each
link in the search field and letting the field's own search-changed signal
run the search. Rendered on the broadway backend, because this machine has
no X display to nest a Xephyr inside; the frames are GTK's own render nodes.

--- two things worth saying about the run --------------------------------

The mid-playlist link and the playlist-first link produced the same frame,
byte for byte, so only one of the two is kept as a PNG. That identity is
the point: the pasted video was Lesson 8, and what came up was Lessons 1
to 3 under a header naming the whole list, exactly as it does for a link
that names no video at all.

The Mix's third row differs between the two sections above - Killer Queen
in the yt-dlp one, Dream On in the window one - because a Mix is
regenerated per request. That is the same property that makes it report
no playlist_count, which is what withholds Add all.
