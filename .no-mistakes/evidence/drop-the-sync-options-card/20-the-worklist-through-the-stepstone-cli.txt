2. The goal the review split out, now filed on its own.

   $ npx -y stepstone@latest project show refuse-a-device-playlist-rename-that
   refuse-a-device-playlist-rename-that: Refuse a device playlist rename that cannot restage the new name
   status: open
   group: Playlists
   created: 2026-08-11T05:25:25.499Z
   updated: 2026-08-11T05:37:11.932Z
   description:
   Renaming a playlist that is already on the iPod takes it off the device and cannot always put it back.
   
   _on_rename_response (ipod_gui/playlist_view.py) renames the local file, calls _stage_playlist(new_name), and then calls _remove_device_playlist(old_name) regardless of whether the staging succeeded. _stage_playlists returns early with the not-queued note when playlist_unavailable is set, so on a machine with no speech engine nothing is staged - and the removal still runs, so ipod-remove.sh strips the playlist off the device. Send to iPod cannot restage it either, because _can_send_playlist also requires speech_engine_available. The playlist leaves the iPod and stays gone until an engine is installed and the user notices they have to re-send it.
   
   It is not a one-line guard, because nothing _stage_playlists hands back says whether staging was possible: it returns "" for non-failure cases as well, so an empty note does not mean "did not stage". Renaming an empty playlist the device holds is the case that breaks the obvious reading. It takes the not-entries-and-not-on-device branch, since the new name is not on the device yet, so nothing is wanted and the call returns "" - while _playlist_on_device(old_name) is still true and the removal is exactly what should run. Skip it there and the old name stays on the iPod as a device-only playlist: its row's Delete still reaches it, but no automatic path takes it off any more, because that name is never staged again. Finding a signal that separates "could not stage" from "nothing to stage" is the actual work, wherever that signal ends up living.
   
   Split out of "Drop the Sync options card and the three add buttons from Device and settings", which corrected the dialog's wording so it stops promising a sync that cannot happen.
